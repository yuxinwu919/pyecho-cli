# ECHO2D 粒子跟踪指南

> 本文档介绍如何使用 ECHO2D-CLI 进行带电粒子束的宏粒子跟踪（Particle Tracking）。
> ECHO2D 当前仅对**旋转对称（round）几何**支持粒子跟踪；矩形（recta）几何暂不支持。

## 概述

ECHO2D 可以在时域求解 wakefield 的同时，跟踪宏粒子在结构中的运动。启用后：

- 每个宏粒子按洛伦兹力方程运动（受本征场与束自场共同作用）；
- 粒子可能因撞到材料边界而**丢失**（`status` 标记）；
- 模拟结束可导出粒子的相空间分布（`particles.out`）；
- 可配合场快照（`Field_XX.bin`）分析粒子轨迹处的场。

ECHO2D-CLI 提供的相关 Python API：

| 功能 | 函数 |
| --- | --- |
| 读取 `particles.out` 二进制 | `load_echo_particles` |
| 计算束流矩（均值 / RMS / 发射度） | `compute_particle_statistics`、`compute_beam_moments` |
| 转换 ASTRA 格式 | `convert_echo_to_astra` |
| 提取粒子轨迹处场 | `see_field` |

---

## 工作原理

启用粒子跟踪后，ECHO2D 在时域迭代的每一步都更新粒子坐标：

1. 由 `InPartFile` 读取初始粒子分布（宏粒子：坐标 + 归一化动量 βγ）；
2. 逐步计算每个粒子所受的电场力与磁场力，更新动量与位置；
3. `ParticleLoss=1` 时，粒子进入材料（导电壁/介质层）即标记为丢失；
4. `DumpParticles=1` 时，最终把粒子相空间写入 `particles.out`；
5. `DumpField=1` 时，把场快照写入 `Field_XX.bin`。

> 动量以**归一化动量 βγ = p/(mₑc)**（无量纲）存储，这与 ECHO2D 内部
> 约定一致。相空间图中动量的单位因此是 βγ，而不是 kg·m/s。

## 逐步操作

### 第 1 步：准备初始粒子分布

`InPartFile` 支持三种输入：

1. **`-`**（默认）：内置高斯笔形束，RMS 长度由 `BunchSigma` 决定；
2. **`*.txt`**：任意纵向束流形状（两列：`s[m]  charge[norm]`）；
3. **`*.bin`**：三维粒子分布二进制文件。

二进制粒子分布格式与 `particles.out` 一致：

- `2` 个 double：`Np`（粒子数）、`q0`（单宏粒子电荷 [C]）；
- `6×Np` 个 double：`x, y, z, px, py, pz`（坐标 [m]，动量 βγ）；
- `Np` 个 int64：`status`（0=存活，1=丢失）。

可参考上游示例：

```
ECHO2D_v3_5/Examples/N15_ParticleTracking/
├── Preprocessor/ASTRA_2_ECHO.m   # ASTRA → ECHO 粒子文件
├── ECHO2D/InParticles/particles.in
└── ASTRA/dlw.0166.001            # ASTRA 源粒子
```

### 第 2 步：配置并运行

在项目里用 `echo2d run start --with-particles` 一键启用粒子跟踪：

```bash
# 1. 初始化项目（round 几何）
echo2d project init my_ptrack -t round_collimator
cd my_ptrack

# 2. 运行并启用粒子跟踪
echo2d run start --with-particles -j 4
```

`--with-particles` 会自动向 `input_in.txt` 追加：

```
ParticleMotion=1
ParticleField=1
ParticleLoss=1
DumpParticles=1
```

> **提示**：若想使用自定义粒子分布，请在运行前把
> `InPartFile=InParticles/particles.in` 写入 `input_in.txt`；
> 否则（`InPartFile=-`）ECHO2D 会使用内置高斯束。

### 第 3 步：分析粒子

模拟结束后，运行目录的 `round/`（或 magn/elec/）子目录下会生成
`particles.out`。执行：

```bash
# 显示相空间统计（Rich 表格）
echo2d postprocess particles .

# 计算并显示归一化发射度
echo2d postprocess particles . --emittance

# 生成 x–px、y–py 相空间散点图
echo2d postprocess particles . --plot

# 全部 + 统计落盘
echo2d postprocess particles . --plot --emittance -o stats.txt
```

### 第 4 步（可选）：转换 ASTRA / 分析轨迹场

```bash
# 转换 ASTRA 格式（用于后续多粒子跟踪代码）
echo2d postprocess particles . --to-astra beam.astra -q 1e-9

# 用 API 提取粒子轨迹处场（Field_XX.bin）
python - <<'EOF'
from pyecho.postprocess.particles import see_field
res = see_field("round/Field_00.bin", "round/Field_01.bin",
                component="Ez", betaz=0.9970847)
print(res["slice_1"].shape)
EOF
```

## 参数参考

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `ParticleMotion` | `0/1` | 是否启用粒子运动方程（`1`=跟踪） |
| `ParticleField` | `0/1` | 是否计算场（`1`=计算） |
| `ParticleLoss` | `0/1` | 粒子进入材料时是否标记丢失（`1`=允许丢失） |
| `CurrentFilter` | `nF` | 对纵向电流分布做 n 次两点低通滤波 |
| `DumpParticles` | `0/1` | 结束是否导出 `particles.out`（`1`=导出） |
| `DumpField` | `0/1` | 是否导出场快照 `Field_XX.bin` |
| `BeamMonitor` | `M1 M2 M3 M4` | 束流矩监视器（时刻范围与步长） |
| `InPartFile` | `-/*.txt/*.bin` | 初始粒子分布（见上文三种方式） |
| `BunchSigma` | 浮点 [m] | `InPartFile=-` 时的高斯束 RMS 长度 |
| `InjectionTimeStep` | 整数 | 粒子注入时刻（时间步数） |

> 参考：`ECHO2D_v3_5/Doc/ECHO_manual.md` §4.3.3（束流设置）、
> §4.3.2（参数表）、§4.7.11（示例 12：介质管中的粒子跟踪）。

## 输出文件

启用粒子跟踪后，在数据子目录（round/）下生成：

| 文件 | 内容 |
| --- | --- |
| `particles.out` | 最终粒子相空间（Np, q0, x/y/z/px/py/pz, status） |
| `Field_XX.bin` | 场快照（Ex, Ey, Ez, Hx, Hy, Hz，ny×nx 网格） |
| `BeamMomentsMonitor.txt` | 束流矩随纵向位置演化（19 列） |
| `wakeL_XX.txt` | 模态 wake 势（与粒子跟踪同算） |

`echo2d run start` 完成后，这些文件会被移动到输出子目录
（round/ 或 magn/、elec/），供 `echo2d postprocess particles`
直接读取。

## 常用命令

```bash
# 一键启用粒子跟踪并运行
echo2d run start --with-particles -j 4

# 查看粒子统计
echo2d postprocess particles .

# 相空间散点图 + 归一化发射度
echo2d postprocess particles . --plot --emittance

# 转换 ASTRA
echo2d postprocess particles . --to-astra out.astra -q 1e-9

# 全程后处理（wake + field + particles）
echo2d postprocess all . --plot
```

## 常见问题（Pitfalls）

### 1. 矩形几何不支持粒子跟踪

ECHO2D 仅对**旋转对称（round）**几何实现粒子跟踪。
若使用 `GeometryType=recta`，`ParticleMotion=1` 不会生效。
请使用 `-t round_collimator` 之类的 round 模板。

### 2. 忘记 `DumpParticles=1`

`ParticleMotion=1` 只让粒子运动，**不会**写出 `particles.out`。
必须同时 `DumpParticles=1`。`echo2d run start --with-particles`
会一次性追加两者，避免遗漏。

### 3. 找不到 `particles.out`

- 确认数据子目录下确有该文件（`ls round/`）；
- 若在项目外单独运行，需在 `output_dir` 中放置 `particles.out`；
- 检查 `DumpParticles=1` 是否已写入 `input_in.txt`。

### 4. 动量单位是 βγ，不是 kg·m/s

`particles.out` 与 ASTRA 转换中，动量均按归一化动量 βγ 处理。
ASTRA 转换时程序会自动乘以 `mₑc²/e`（≈510998.95 eV/c）还原为
ASTRA 的 eV/c 单位。

### 5. 粒子丢失过多

若大量粒子 `status=1`，通常意味着网格过粗或束太靠近材料边界：

- 细化网格（减小 `StepY` / `StepZ`）；
- 检查几何文件中束通道半径是否足够大；
- `ParticleLoss=0` 可关闭丢失标记（不推荐，会掩盖真实物理）。

### 6. 收敛性

与 wake 收敛一致：束 RMS 长度 `BunchSigma` 上至少应有约 5 个网格点
（`σ/h_z ≥ 5`）。粒子跟踪同样依赖足够细的纵向网格来正确解析
束自场与 wake 的作用。

### 7. 运行后 `input_in.txt` 被恢复

`echo2d run start` 在每次子运行后会把 `input_in.txt` 恢复为运行前
内容（用于正确的 `SymmetryCondition` 切换），但 `--with-particles`
追加的粒子参数会保留。若后续不需要粒子跟踪，手动删除这几行即可。
