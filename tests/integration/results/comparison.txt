NOTES / ROOT CAUSE
----------------------------------------------------------------------
All 6 FAILs are flat (recta) geometry. Root cause: pyecho/api.py
_postprocess_flat() computes loss/kick factors as UNWEIGHTED integrals:

    loss_long  = -trapz(Wlong, s)     # pyecho/api.py:351
    kick_quad  = -trapz(Wquad, s)     # pyecho/api.py:352
    kick_dipole = -trapz(Wdipole, s)  # pyecho/api.py:353

MATLAB's LossShape.m weights by the bunch profile:
    loss = -sum(lambda(s) * W(s)) * ds

Recomputing the same runs with the bunch-weighted loss path
(pyecho/postprocess/wakes/recta.py _add_bunch_and_loss_factors, which
mirrors LossShape.m) gives agreement with MATLAB to 0.000% for every
flat run (N4, N5, N6, N7, N8, N12) — so the wake physics is correct;
only the CLI summary-loss definition is wrong (bunch weighting omitted).

Round geometry passes because _postprocess_round() uses the bunch-weighted
loss_factor from the round wake processing (LossShape-equivalent).
